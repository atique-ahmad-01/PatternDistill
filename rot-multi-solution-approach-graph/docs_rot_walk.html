Stage 0 · offline, once

Build the graph

Every validated teacher solution becomes a template; each of its reasoning steps becomes a node. Two edge types are laid over those nodes.

step nodes2,450
templates651
sequential edges1,799
semantic edges598,636

Sequential edges join step i to step i+1 inside one solution — there are exactly 2,450 − 651 = 1,799 of them. Semantic edges join steps across different solutions whenever raw cosine ≥ 0.85, embedded with jina-embeddings-v2-small-en. 281,226 of them cross technique families.

Stage 1 · the query

A problem the baseline got wrong

In Wythoff's game the cold (losing) positions are indexed k=1,2,3,.... What is the SMALLER pile size of the 255-th cold position?

Gold answer 412 · family wythoff. Unaided, the model answered 255 after 5,001 output tokens and 34.0s.

Stage 2 · candidate filter

2,450 nodes → 155

Nodes are kept only if their knowledge tag matches the query's (wythoff), and dropped if they come from the query's own problem. That second rule is the leakage guard — it is enforced in code and cannot be switched off in config.

Stage 3 · pick the entry point

First node: 0.75 × cosine + 0.25 × [is step 0]

The query is embedded once and scored against all 155 candidates. The bonus biases the walk toward starting where a real solution starts, without abandoning query alignment. Winner: q0070_s2 at cosine 0.9033.

Stage 4 · the walk

Eight steps, four source solutions

From each node the walk scores every successor as 0.3 × cosine + 0.7 × [is the sequential child] and takes the best. Because a sequential child scores at least 0.7 and a semantic neighbour at most 0.3, the walk always continues through its current solution until that solution runs out of steps — then it jumps.

This is the whole intervention. The template sits in the user turn as reference material — "use the given steps if applicable otherwise use them to guide your reasoning". The model then starts from an empty assistant turn and is free to reject it.

The published RoT method instead prefills the template into the assistant's own <think> block, so the model resumes mid-sentence from reasoning it appears to have already committed to. Same template, same graph, same walk — 16.7% instead of 81.2%.

What it did
Recited the template back verbatim, Step 1 through Step 8, and stopped. No arithmetic on k=255 appears anywhere.
Where 27 came from
Step 3 of the template: "compute 17·φ ≈ 27.50658, and take the floor to get 27." That is the answer to a different problem — the one this step was originally written for, where k=17. The model copied the constant out of someone else's worked example.
Why the prefill causes it
Thinking Intervention hands the template over as reasoning the model appears to have already performed and committed to. There is no turn at which it can evaluate whether the steps apply. It wakes mid-sentence after "Using step 1" and the only coherent continuation is to carry on reciting.
Not a parsing artefact
0/48 replies ever close <think>, yet format compliance is perfect — 48/48 used \boxed, 0 unparseable, 0 truncated. The answer extractor reads these correctly. The model genuinely answered 27.
Cost of stopping early
261 output tokens and 1.6s, against 3,256 tokens and 22.4s for the user-turn run that got it right. The token saving is real; it is the saving of not doing the work.

Across all 48 problems: 8/48 correct (16.7%) against the baseline's 75.0% — −58.3 points. Mean generation 1,276 characters, and thinking collapses from 2,754 tokens unaided to 524.

The instance-bound constants in the template are necessary for this failure but not sufficient. The user-turn run received the same template, containing the same "get 27", and answered 412 — because it was free to read the step as an example rather than as its own conclusion.
