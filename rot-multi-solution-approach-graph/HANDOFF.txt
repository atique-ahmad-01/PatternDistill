--------------------------------------------------------------------------------
1. WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
Retrieval-of-Thought. A teacher (Qwen3-8B) solves each training problem five
independent ways; each solution is parsed into an APPROACH plus ordered
mini-subtasks. Those become a memory bank and an approach/subtask graph. At test
time the nearest approaches are retrieved into a Qwen3-1.7B prompt, and the
student is benchmarked with and without them.

Question under test: does handing a small model someone else's reasoning
strategy help it solve problems it cannot crack alone — and is it the RETRIEVAL
that helps, or would any worked example do?

7. MISTAKES ALREADY MADE — DO NOT REPEAT
--------------------------------------------------------------------------------
* `pkill -f <pattern>` KILLED MY OWN SSH SESSION TWICE, because the pattern
  matched the ssh command line carrying it. Always kill by exact PID.

* Xet (the HF downloader) takes 30-60s to negotiate and ramp up. Measuring
  inside that window looks exactly like a stall. I concluded "stalled" and
  killed a working download repeatedly — that, not the network, cost the most
  time. LET DOWNLOADS RUN. Poll at multi-minute intervals, not seconds.

* HF downloads do NOT resume cleanly: each restart writes a fresh
  *.incomplete blob with a new random suffix. Restarting throws away progress.

* HF_HUB_ENABLE_HF_TRANSFER is DEPRECATED in huggingface_hub 1.23 (Xet replaced
  it). Setting it does nothing. HF_XET_HIGH_PERFORMANCE=1 is the replacement.

* Summing /sys/class/net/*/statistics/rx_bytes includes lo and docker0 and
  wildly overstates external throughput. Measure the real interface (wlp13s0).

* `docker pull` keeps downloading even when the CLIENT process is SIGSTOPped —
  dockerd owns the transfer. Kill the client to actually stop it.

* SIGSTOP on the HF downloader breaks its worker threads; it stays alive but
  transfers nothing. Don't suspend it, and don't trust "process alive" as proof
  of progress — check /proc/<pid>/io write_bytes.

8. DESIGN DECISIONS WORTH PRESERVING
--------------------------------------------------------------------------------
* THE SPLIT IS FROZEN to data/artifacts/split.json and reused by every stage.
  Re-deriving it per command meant a seed edited between `generate` and
  `evaluate` would silently move the train/test boundary, putting an
  already-solved problem into the test set. The memory bank would then hold a
  solution to a problem the student is scored on — invalidating the run while
  every stage still reported success. Changing split settings after freezing is
  now a loud error. --refresh-split re-splits deliberately.
  Limits (--limit-train/--limit-test) are a VIEW on the frozen split and can
  never move the boundary.

* PER-FAMILY SPLIT (9 train / 3 test in every one of the 16 families). A global
  shuffle can leave a technique absent from test, and technique reuse is the
  entire experiment.

* ARM B (random memory) is the control that makes the result interpretable.
  Without it a gain in C/D could be "any worked example helps" rather than
  "retrieval found the right memory" — completely different claims.

* THINKING MODE IS ON for both models, and thinking tokens are reported
  SEPARATELY from answer tokens. The claim is that a retrieved approach removes
  the need to SEARCH for a strategy; that search lives in the reasoning trace.
  Measuring only final-answer length would test a much weaker claim.
  Student temperature is 0.6, NOT greedy — Qwen3's guidance is explicit that
  greedy decoding in thinking mode degrades quality and can loop forever. Seed
  is pinned instead so arms stay comparable.

* SAME-FAMILY RETRIEVAL RATE is reported per arm. RB-DERIV families share one
  technique, so landing in the right family explains most of any effect. Hiding
  it would let family-matching read as semantic understanding.

* The project is FULLY SELF-CONTAINED — no file outside its own directory is
  read. data/RB_DERIV/ is the one canonical copy of the dataset in the whole
  repo (duplicates in archive/phase-7 and archive/sep-paper were deleted).
  .gitignore is scoped to data/artifacts/ — do NOT widen it to data/, that
  would exclude the dataset from git and break self-containment.
