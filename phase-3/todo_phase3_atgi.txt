PHASE-3 TODO — Adaptive Thought Graph Injection (ATGI)
======================================================

Core idea: Decompose existing patterns into a step-level thought graph,
use subject-filtered retrieval + reward-guided traversal to assemble a
custom reasoning template per problem, and pair it with the best-matching
worked example.

Combines best of: RoT (step graph + traversal) + BoT (template reuse)
                  + Phase-2d (worked examples + per-subject thresholds)


STEP 1: Build Step-Level Thought Graph
---------------------------------------
Input:  phase-2d/memory/bank.json (400 patterns)
Output: phase-3/graph/thought_graph.json + step_embeddings.npy

  [ ] 1.1  Parse all 400 patterns into individual steps
         - Split on "Step 1:", "Step 2:", "Step 3:", "Note:"
         - Each step becomes a graph node with metadata:
           {step_id, pattern_id, step_index, text, subject, level}
         - Expected: ~1200-1600 nodes

  [ ] 1.2  Embed every step using nomic-embed-text (768-dim)
         - Batch embed all step texts
         - L2-normalize for cosine similarity
         - Save as numpy array + FAISS index

  [ ] 1.3  Build sequential edges
         - Connect (pattern_id, step_i) → (pattern_id, step_i+1)
         - Weight = 1.0
         - Within-pattern order preserved

  [ ] 1.4  Build semantic edges
         - For all cross-pattern step pairs:
           if normalized_cosine_sim >= τ_semantic (0.80):
             add bidirectional edge with weight = sim score
         - This enables cross-problem step recombination
         - τ_semantic = 0.80 (slightly lower than RoT's 0.85
           because nomic-embed-text differs from jina)

  [ ] 1.5  Store graph structure
         - Adjacency list format (JSON)
         - Node metadata + edge list + edge weights
         - Pre-computed step embeddings (numpy)


STEP 2: Subject-Aware Initial Node Retrieval
---------------------------------------------
At inference time, given a test problem Q:

  [ ] 2.1  Embed the test problem Q with nomic-embed-text

  [ ] 2.2  Filter candidate nodes by subject
         - Only consider nodes whose subject matches Q's subject
         - This prevents cross-subject noise
           (learned from phase-2b: global retrieval + subject
            thresholds works, but filtering candidates is cleaner
            at step level)

  [ ] 2.3  Score all candidate nodes:
           R_initial = α · sim(Q, node) + (1-α) · is_first_step
         - α = 0.8 (prioritize semantic relevance)
         - is_first_step bonus = 1.0 if step_index == 0, else 0.0
         - This biases toward entry points of reasoning chains

  [ ] 2.4  Select top initial node: v_0 = argmax(R_initial)
         - Apply per-subject similarity threshold from phase-2d:
           IA=0.60, NT=0.65, Precalc=0.65, Geom=0.55, default=0.50
         - If best score < threshold → skip injection (vanilla only)


STEP 3: Reward-Guided Graph Traversal
--------------------------------------
Starting from v_0, greedily expand the template:

  [ ] 3.1  Initialize template T = [v_0]

  [ ] 3.2  At each expansion step, evaluate neighbors:
           R_traverse = β · sim(Q, neighbor) + (1-β) · R_flow
         - β = 0.6 (balance relevance vs structure)
         - R_flow = 1.0 if neighbor is sequential successor
                    0.5 if neighbor is semantic edge
                    0.0 otherwise
         - Select v* = argmax(R_traverse)

  [ ] 3.3  Append v* to T

  [ ] 3.4  Termination conditions (any one triggers stop):
         - max(R_traverse) < τ_stop (0.40)
         - len(T) >= max_steps (6, tuned for 1.7B context)
         - no valid candidate neighbors remain

  [ ] 3.5  Deduplicate: if assembled template has near-duplicate
         steps (sim > 0.95), keep only the higher-scoring one


STEP 4: Hybrid Prompt Construction
------------------------------------
Combine assembled step template + best worked example:

  [ ] 4.1  From traversal: assembled reasoning strategy (steps)

  [ ] 4.2  From phase-2d bank: retrieve the worked example from
         the FULL pattern with highest overall similarity to Q
         (top-1 from existing FAISS index — same as phase-2d)
         - This gives concrete symbolic manipulation alongside
           the abstract assembled strategy

  [ ] 4.3  Build injection prompt:
         SYSTEM: "You are a precise math problem-solving assistant.
                  A Reasoning Strategy assembled from similar problems
                  and a Reference Example are provided. Follow the
                  strategy steps, adapting them to this specific problem."

         USER:   "Reasoning Strategy:
                  Step 1: {assembled_step_1}
                  Step 2: {assembled_step_2}
                  Step 3: {assembled_step_3}
                  [...]

                  Reference Example:
                  {best_matching_worked_example}

                  Problem: {problem}

                  Solution:"

  [ ] 4.4  Also run vanilla (no injection) for comparison


STEP 5: Evaluation Pipeline
-----------------------------
  [ ] 5.1  Run on 100 held-out test problems (MATH-500[400:500])
         - For each problem: vanilla + ATGI injection
         - Record: accuracy, similarity scores, traversal path,
           template length, latency, token counts

  [ ] 5.2  Parse and compare answers (same logic as phase-2d)

  [ ] 5.3  Generate summary stats:
         - Overall: vanilla vs ATGI accuracy, delta
         - By subject (7 subjects)
         - By difficulty level (1-5)
         - By traversal length (how many steps assembled)
         - By edge type used (sequential-only vs mixed)

  [ ] 5.4  Compare against phase-2d baseline:
         - Phase-2d: 70% → 76% (+6.0pp)
         - Target: beat +6.0pp delta


STEP 6: Analysis & Diagnostics
--------------------------------
  [ ] 6.1  Log per-problem traversal paths
         - Which patterns contributed steps?
         - How many cross-pattern (semantic) edges used?
         - Are assembled templates actually novel combinations?

  [ ] 6.2  Analyze failure modes:
         - Problems where ATGI helped vs phase-2d didn't
         - Problems where ATGI hurt vs phase-2d didn't
         - Correlation between traversal length and accuracy

  [ ] 6.3  Subject-level insights:
         - Does cross-pattern assembly help Geometry? (0pp in 2d)
         - Does it help Number Theory? (0pp in 2d)
         - Does Level-1 regression persist?

=== KEY DESIGN DECISIONS ===

WHY this hybrid beats pure approaches:

vs Pure Top-K (3A):
  - Top-K dumps 3 full patterns → overwhelms 1.7B context
  - ATGI selects only the RELEVANT steps → lean, focused prompt

vs Pure BoT (3B):
  - BoT needs extra LLM call for problem distiller → adds latency
  - BoT templates are high-level abstractions → lose procedural detail
  - ATGI keeps concrete step-level procedures (proven in phase-2d)

vs Pure RoT (3C):
  - RoT assembles steps only, no worked example
  - ATGI adds best-matching worked example (proven in phase-2d)
  - RoT uses jina embeddings, we adapt for nomic-embed-text
  - ATGI adds subject-filtered retrieval (learned from phase-2b/2d)

HYBRID ADVANTAGE:
  RoT's dynamic step assembly (novel combinations)
  + phase-2d's worked examples (concrete symbolic grounding)
  + phase-2d's per-subject thresholds (selective injection)
  = Best of all worlds in one pipeline


=== HYPERPARAMETERS TO TUNE ===

  α = 0.8          (initial node: semantic vs structural weight)
  β = 0.6          (traversal: semantic vs flow weight)
  τ_semantic = 0.80 (semantic edge threshold)
  τ_stop = 0.40    (traversal termination threshold)
  max_steps = 6    (max assembled template length)
  k_example = 1    (number of worked examples to include)
